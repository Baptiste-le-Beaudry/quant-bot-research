## Relecture du code de référence et corrections (commit 643179f, avant tout calcul sur P2)

- **Conformes au texte :**
  - états Donchian : entrée si le close dépasse le max des n closes précédents ; sortie si le close passe sous le milieu des n derniers closes, aujourd'hui inclus ; sinon l'état est conservé ;
  - signal = moyenne des 9 états ;
  - σ sur 60 jours × √365 ;
  - décision à J, détention sur J+1 (`shift(1)`). Aucun lookahead : un test perturbe les prix après J et vérifie que les poids jusqu'à J ne changent pas.
- **Écart 1, formule du poids.** La référence calcule `clip(signal × 0,25/σ, 0, 1)/3`, alors que le texte dit `signal × min(1 ; 0,25/σ)/3`. Les deux diffèrent quand σ < 0,25 et que le signal est strictement entre 0 et 1 ; la référence donne alors un poids plus grand. J'ai corrigé selon le texte. **Effet nul ici** : σ n'est jamais descendu sous 0,25 un jour investi (minimum 0,264 pour BTC, 0,303 pour ETH, 0,430 pour SOL), et l'écart de poids maximal vaut 0.
- **Écart 2, close de 00:00 UTC.** Avec `closed='right'`, la référence prend le close de la barre 1 min ouverte à 00:00, c'est-à-dire le prix à 00:00:59. Le texte dit « close à 00:00 UTC ». J'ai donc pris le close de la barre ouverte à 23:59 (`closed='left'`, `label='right'`). Les jours sans aucune barre seraient complétés par le close précédent ; il n'y en a aucun.
- **Écart 3, rotation.** La référence ignore la dérive des poids, alors que son PnL suppose un rebalancement quotidien vers la cible. Le coût porte maintenant sur |cible − poids dérivé|, ce qui est plus conservateur.
- **Mesure du MaxDD.** L'équité part maintenant de 1, ce qui fait compter une perte dès le premier jour.
- **Sensibilité :** le code de référence exécuté tel quel sur P2 donne CAGR −0,76 %, Sharpe −0,06, MaxDD −11,9 %. C'est aussi un REJET : les corrections ne changent pas le verdict.
